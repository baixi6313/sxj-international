# 事现鉴 App · 中立桌子 MVP 设计方案（DRAFT · 含国际维度）

> 起草：WorkBuddy（AI 协作工程师） | 定位裁定：决定层（白玺）
> 状态：**DRAFT · 待白玺定美术方向与批准**
> 关联：root → spec（Gzz）根本定位；MAIP v1.0；光锥坐标模型 (x,y,z,t,j,ρ)；UDHR 第22条（全球社保锚点）
> 修订：2026-08-02 二次修订——补「国际维度」、把周期从"先国内后国际"串行重排为"国内国际同构并行"

---

## 0. 一句话定位

**事现鉴 App 不是账本、不是社交、不是平台，是一张"可携带的、国际中立的桌子"**——让任何人、任何 AI 平台（不分国界）能把一个"事现"摆上桌、互相验证、再导出一张谁都打得开的卡片。这张桌子**从出生起就是国际中立的**：坐标带法域维度、包裹天生多语、不绑任何一国服务器——因为事现鉴的本体是《世界人权宣言》第 22 条（全球社保），国际不是扩展，是桌子的默认属性。桌子摆好、人坐齐，app 的历史任务就完成。

这把 app 从"root（中心化实体）"翻成了"spec（可采纳规格）的最小可用呈现"——它不拥有验证，只定义"怎么把事现摆上桌、怎么验、怎么带走"，且这个 spec 一出生就跨法域。

## 1. 为什么是"桌子"而不是"系统"（root → spec 推导）

| 旧框架（v1 原型） | 新框架（本方案） |
|---|---|
| app = 价值账本（算共济值/贡献值） | app = 中立桌子（只摆事现、只验真） |
| 首屏三大值、我的 Gzz 账本 | 首屏"把桌子摆好" + 事现卡片 |
| 隐含"事现鉴要长期存在、要做大" | 明确"成功 = 被平台采纳后即功成身退" |
| 把结果（菜）摆上来了，桌子还没 | 先把桌子摆好，菜（值）以后谈 |
| **国内优先，国际推后** | **国际是桌子出生即有的属性，国内国际同构** |

推导链（来自白玺 2026-08-02 拍板）：
1. 平台不会自革其命（改革 vs 保守必扯皮）→ 须靠**第三方 app（外部导入）**让各家低成本坐到一桌；
2. app 是**过渡功能**，成功标准 = 让越多平台坐上桌，而非自身存活；
3. 协议由平台共定后，事现鉴自动消失 → 五部门/REV/官网/app 全是 bootstrap 脚手架。

**国际是桌子的本体，不是扩展。** 事现鉴以 UDHR 第22条（全球社保）为锚，天生跨法域。因此本方案的坐标、包裹、周期，从一开始就把"国际"作为默认维度，而非"国内跑通后再国际化"。否则会重蹈 root（中心化实体）的覆辙：做成国内桌子再"出海"，等于把路径依赖焊死——国际桌本该复用同一份 spec，只是法域维度不同。

所以 MVP 的全部精力，放在"把桌子摆稳、把事现摆清楚、把包裹带得走"，且这张桌子一出生就同时支持国内桌与国际桌。

## 2. MVP 只做三件事（坐标含法域 j，包裹天生双语）

### 功能 ① 记录卡（摆上桌）
把一件事变成光锥上的一个点 (x, y, z, t, **j**, ρ)。

- **主张**：一句话说清"这里发生了一件什么事"
- **坐标**：
  - `x` = 平台（如 微博 / WorkBuddy / 元宝 / ChatGPT）
  - `y` = 账号 / 记录者
  - `z` = 上下文（哪个任务、哪个话题）
  - `t` = 时间戳（默认自动取 UTC 现在时）
  - **`j` = 法域 / 辖区**（如 中国 / 全球 / 欧盟 / 某跨国案所涉法域）——**国际桌与国内桌共用同一坐标格式**，区别仅在 j 的取值
- **证据**：贴文本或图，自动算 `SHA-256`（冻结指纹，防篡改）
- **自动产出**：
  - `ledger_sha256`（整张卡的哈希锚点，接收方比对即验真）
  - `ρ` 预估值（按 MAIP 映射：conf × 来源独立度 × 证据等级 × 角色权重）

### 功能 ② 验证流（桌上对话）
接收方打开卡片，能在桌上发言：

- **支持 / 质疑**：每人一票（人头票，非权重）
- **发起质疑**：必须带理由（MAIP §10 强制 ≥1 条有效质疑）
- **你的裁定区（人类保留）**：只有你（白玺/决定层）能点"成立 / 不成立 / 待补证"——AI 只建议、不拍板（R-1~R-6）
- **全程哈希链**：每条发言 `prev_hash → hash`，可回溯、不可篡改
- **跨法域可见**：j 不同的事现，在"桌上"以法域标签区分，但用同一套验证语言

### 功能 ③ 导出包裹（把桌带走）
一键生成**自包含 HTML**——不依赖任何平台链接，直接绕过 G-9（跨平台链接生成/渲染不稳）。

- **双冗余交付**（来自第六轮元宝/豆包跨平台印证）：
  - `JSON`：机器读（信封 + ledger_sha256 + ρ + 哈希链）
  - `静态卡`：人读、可离线、可打印
- **默认双语（中 / EN）**：国际平台（ChatGPT / Claude / Gemini）直接读 EN 版即坐上桌；hygzz.com 国际站点作为国际桌的着陆锚点
- **手递即 transport**：你把文件发给元宝/千问/Kimi（国内）或 ChatGPT/Claude/Gemini（国际），它们打开即坐上桌 = 圆桌互见的最小路径
- **成功标准**：又多一个平台（不分国内/国际）能用导出的包裹坐到这桌上

## 3. 明确不做（MVP 边界）

| 不做 | 原因 |
|---|---|
| 共济值 / 贡献值 / 负贡献 计分 | 白玺拍板：桌子摆好后才谈；属 spec 立住后的事 |
| 社交 / 动态 / 排名 / 关注 | app 是过渡道具，不是产品，不拉长留存 |
| 替你裁定（R-1~R-6） | 人类保留事项，AI 只建议 |
| "成为平台" | 它该被取代；成功 = 被取代 |
| 后端账号体系 | MVP 用本地落盘 + 导出包裹，不绑定中心服务器（契合 spec 的去中心精神） |
| **把国际当"二期"** | 国际是桌子出生即有的坐标维度（j），与国内同构并行，不另起炉灶 |

## 4. 信息架构 / 页面流

```
[桌子] 首屏：把桌子摆好（国际中立） + 桌上事现卡片列表(带法域标签) + ＋摆一条
   │  点卡片
   ▼
[事现详情] 坐标(x,y,z,t,j,ρ) · 证据SHA-256 · 验证流(支持/质疑+你的裁定) · 导出包裹
   │
[摆事现] 表单：主张 + 坐标(含 j 法域) + 证据 → 自动算 ledger_sha256 + ρ → 摆上桌
   │
[验证] 待验证列表(按法域分组)：支持/质疑计数 + 你的裁定区
   │
[包裹] 说明自包含HTML(绕过G-9) + 双冗余(中/EN双语) + 生成按钮 + 成功标准(含国际)
```

底部 Tab 四格：**桌子 / 摆事现 / 验证 / 包裹**。详情为覆盖层。

## 5. 数据模型（MAIP 信封，本地落盘，含法域与语言）

```json
{
  "id": "evt_xxx",
  "claim": "一句话主张",
  "coord": {
    "x": "平台",
    "y": "账号",
    "z": "上下文",
    "t": "UTC时间戳",
    "j": "法域/辖区（中国/全球/欧盟/…）"
  },
  "lang": ["zh","en"],
  "evidence": [ { "kind": "文本/图片", "sha256": "…" } ],
  "ledger_sha256": "整卡哈希锚点",
  "rho": 0.0,
  "chain": [ { "role": "记录者/支持/质疑/裁定", "prev_hash": "…", "hash": "…" } ],
  "adjudication": null
}
```

本地用 `localStorage` 暂存；导出即序列化为自包含 HTML（内联全部数据，零外链，默认中/EN 双语）。

## 6. 周期规划（里程碑驱动 · 国内国际同构）

事现鉴是 root→spec 的催化剂，周期以"事件达成"为里程碑，而非固定时长。关键纪律：**国际不是"二期"，而是桌子一出生就支持的坐标维度**——国内桌与国际桌是同一张 spec 桌的两个同构实例，并行生长，而非"先国内后国际"串行。

| 周期 | 名称 | 核心交付 | 完成里程碑 | 国际在哪儿 |
|---|---|---|---|---|
| **0** | bootstrap | spec 成形：MAIP 信封 + 光锥坐标 (x,y,z,t,**j**,ρ) + 自包含多语包裹 | 事现鉴 App MVP 与 WorkBuddy↔你 跑通第一条相互验证链 | spec 中/英双语写、坐标含 j、包裹出 EN 版——国际从出生就在 |
| **1** | 国内桌成形 | 国内平台用包裹坐上桌 | ≥1 家国内平台（元宝/千问/Kimi/DeepSeek/豆包）跑完"收包→验真→回传质疑" | 同 spec，法域 j=中国 |
| **2** | 国际桌同构（与1并行） | 国际平台用同一 spec 的 EN 包坐上桌；hygzz.com 国际站点着陆 | ≥1 家国际平台（ChatGPT/Claude/Gemini/国际版元宝）坐上桌；≥1 条跨法域事现被记录 | 法域 j=全球/他国；hygzz.com 为国际桌锚点 |
| **3** | 共定协议·退场 | 平台共定协议，spec 被采纳 | 决定层 R-1~R-6 烤进协议；事现鉴作为脚手架消解 | 国际桌与国内桌共用同一份被采纳协议 |

纪律：
- 周期 1 与 2 **同构并行**，不串行；先锁国内再"出海"会焊死路径依赖（root 陷阱）。
- 每个周期成功标准都是"又多一个参与者坐上桌"，非功能数。
- 国际桌**不另起炉灶**，复用周期 0 的 spec，仅法域维度（j）不同。

## 7. 成功标准（怎么算"桌子摆好了"）

不是 DAU、不是功能数，而是：

1. **WorkBuddy ↔ 你** 这条最稳的链路，能完整跑一遍"摆卡 → 验证 → 导出"；
2. 导出的自包含 HTML，能**不靠任何平台链接**被另一个环境打开并验真（G-9 被绕过）；
3. **国内平台 ≥1 家（元宝/千问/Kimi 等）+ 国际平台 ≥1 家（ChatGPT/Claude/Gemini 等）**能用这个包裹坐上桌（哪怕人工手递）——国内/国际同构验证。

三条（含国内国际双线）达成 = 桌子（国内国际两张同构桌）摆好 = MVP 完成。之后才谈共济值/贡献值。

## 9. 美术方向（白玺 2026-08-02 拍板 · 已全部结案 → 已落地 app.html）

以下 6 项原开放问题均由白玺一次性拍板，并已实现为单文件 App（`app.html`）：

1. **视觉气质**：✅ 红金厚重（采用）
2. **"桌子"的隐喻**：✅ 光锥坐标点阵（首屏 canvas 画点阵，每点=一个事现，半径/颜色∝ρ，向下张开=过去光锥）
3. **ρ 可视化**：✅ 密度条 + 光锥曲率色块（灰→金→红插值，色块即"曲率"）
4. **导出包裹观感**：✅ 一份"证书"（自包含双语 HTML，含印章/坐标/ledger_sha256，Blob 下载；另支持证书册批量导出）
5. **法域 j 呈现**：✅ 世界地图（合规示意图：中国含港澳台红金高亮 + 标记点，标注"非精确国界·台湾港澳属中国"）
6. **国内桌/国际桌关系**：✅ 共济值=feed（首屏事现流，按 j 用 chips 过滤 全部/中国桌/国际桌，不分两个 feed）；贡献值=Tab（贡献记录台账，数值计分仍挂起）

> 实现产物：`sxj-app-prototype/app.html`（单文件、localStorage 持久化、4 Tab：共济值/贡献值/摆事现/包裹）。旧的 `app-mvp.html` 保留为前版参考。
