事现鉴（SXJ）· 产品定位说明

基于《世界人权宣言》第 22 条的可验证公共事实协议 · 公共验算尺
小程序 · 前锋 原生 App · 主场 不推销真理，只给防忽悠的免疫系统

一句话定位

事现鉴是一把统一度量衡的公共验算尺：不替你下结论，只把"谁、在什么时间、凭什么说这件事"做成可验证、可回溯、不可篡改的公共记录。它不取代任何国家的社保，而是让"共济值 / 贡献值 / 负贡献"三值在统一规则下能被任何人独立验算。

双端口策略：一个产品，两种入口

同一套协议、同一套设计语言，但按用户习惯分两个入口——微信小程序当"前锋"广撒网，原生 App 当"主场"沉淀重度用户。两者不是二选一，是漏斗关系。

已上线 微信小程序

角色：前锋 / 广撒网入口

  • 对应"已经在微信里的人"
  • 最广普通大众，尤其中老年、数字素养低者
  • 事件当事人 / 目击者（如彬县退休职工家属，日常就在微信群）
  • 验证团里的非技术成员，微信友好零学习

规划中 原生 App

角色：主场 / 重度工作台

  • 对应"愿意为这事专门留个应用的人"
  • 重度 / 高频用户：验证团核心、长期记录者
  • 在意"中立、不被平台挟持"的人
  • 海外 / 非微信生态用户，可双商店出海
一句话概括：小程序找"路过的人"，App 留"留下的人"。

最大的区别：入口归谁所有

小程序是"寄生"在微信里的——用户其实属于微信，你只是微信里的一个小服务。微信哪天改规则、限流、甚至封你，你几乎没有还手之力。

App 是你自己的地盘——用户装在你这，品牌、数据、推送都归你。代价是你要自己把人拉来装。

对事现鉴特别要命的一点：我们的调性是"公共、中立、可验证"。一个依赖单一商业平台的工具，在"公共中立"这件事上天然有张力——平台自己就能定义什么能发、什么不能发。这也是为什么 App 必须存在，作为中立主场。

引导转化
从"路过"到"留下"——被价值吸引，主动装 App

用户从微信被吸引过来，装 App 时不觉得是换了个产品——因为两边长得像一家。

关键澄清：私域的是"主场"，公开的是"账本"

事现鉴是私域平台吗？是，也不是——要看说的是哪一层：

① 私域的是"主场 / 关系"：用户最终沉淀在你自己的 App 里，渠道与关系归你所有，不依附于任何单一商业平台。这正是"私域"真正的精神——把命根子从别人手里拿回来，抗限流、抗封禁、保中立。

② 公开的是"数据 / 内容"：所有事现记录、证据、哈希链、SHA-256 锚点完全公开、可验证、可回溯、可跨端比对。任何人都能独立验算，平台无权偷偷改、也不能定义"什么能发"。

两层正交、不矛盾：壳是私域的（主权在你），核是公共的（账本归所有人）。一句话——私域主场，公开账本。
对应到技术上：App = 自有主权终端（私域主场）；哈希链 / SHA-256 锚点 = 公开可验证账本（公共协议）。两者一结合，就是"既私域又公共"的架构答案。

下一步：视觉统一（不论谁是旗舰，先长得像一家）

当前原型、小程序、安卓三套的配色变量已一致，但布局 / 结构 / 文案是分开写的，所以看着仍像两个产品。建议优先做低成本、立刻见效的视觉统一：
  • 统一品牌红 #A32D2D + 金 #C9A24B 与三值色（蓝 / 金 / 珊瑚）；
  • 统一按钮位置、卡片结构、状态标签文案；
  • 统一"转发 / 跟贴"交互范式，确保跨端体验一致。
技术形态（HTML 原型 / 小程序 / RN 真 App）暂不强行合并——原型继续当"图纸"，定稿后落真代码。
