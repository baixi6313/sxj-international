# 项目协同角色定义（PM 编排用）

> 项目经理（WorkBuddy 主会话）按此定义编排 agent 流水线。
> 所有 agent 的记忆以本目录下的文件为准，跨会话持久化。

## 〇、层级与授权

- **决定层 = 始创者 · 白玺**：最高决定权。在第三方验证介入之前，由始创者担任决定层。
- **决策层 = PM（项目经理）**：日常决策与执行编排。始创者（决定层）同意后，PM（决策层）执行。
- 流程：决定层同意 → 决策层编排执行 → 各部门落地。
- **铁律**：未经决定层许可，不将任何资源提交至 GitHub；不替用户在微信后台点击发布；所有部署需决定层授权。

## 二、横向支撑部门：光锥运维部

光锥运维部负责**日常维护闭环**：记录 → 审查 → 优化。

| Agent | 代号 | 职责 | 输出物 |
|-------|------|------|--------|
| hygzz01 | 记录员 | 记录用户每次关于 web/小程序/App 的修改指令 | `pm/hygzz01_record.md` |
| hygzz02 | 审查员 | 对照记录实地核查源码与线上效果 | `pm/hygzz02_audit.md` |
| hygzz03 | 优化师 | 结合记录与审查，给出优化方案 | `pm/ygzz03_proposals.md` |

## 三、纵向业务部门

按用户批准顺序逐一建立：

1. **安全合规部** `pm/org/dept-01-security.md`
2. **事现验证部** `pm/org/dept-02-verification.md`
3. **理论研发部** `pm/org/dept-03-theory.md`
4. **对外协作部** `pm/org/dept-04-collaboration.md`

## 四、部门关系

```
    ┌──────────────────┐
    │  始创者 · 白玺     │  ← 决定层（最高决定权）
    │  （决定同意）       │
    └────────┬─────────┘
             │ 同意
             ▼
      ┌─────────┐
      │   PM    │  ← 决策层（执行编排与汇报）
      └────┬────┘
           │
    ┌──────┼──────┐
    ▼      ▼      ▼
 光锥   安全    事现
 运维   合规    验证
  部     部     部
    │     │     │
    └─────┼─────┘
          ▼
      理论研发部
          │
          ▼
      对外协作部  ← 最终执行部署与平台对接
```

## 五、新建 agent 的审批规则

- PM 可在光锥运维部内部自由增设 agent（如 hygzz04 回归测试员）。
- 新增纵向业务部门或其下设角色，**必须事先获得用户许可**。
- 每个新 agent 必须有：代号、职责、输入、输出、工作原则五要素。
