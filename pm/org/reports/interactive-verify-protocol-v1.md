# 事现鉴 · 交互验证治理协议 v1

> 状态：草案（待决定层·白玺确认生效）
> 前身：SXJ-verification-ledger.md 第零章（检验成功协议）、edu-docking-protocol-v1.md（教育对接协议）
> 本轮新增（相对"相互验证"）：① 三层同心圆；② 层二对外环的"挑战/推翻权"；③ 以共创论核心理论为判准的边界。

---

## 0. 核心定义：交互验证 ≠ 相互验证

| | 相互验证（旧） | 交互验证（本协议） |
|---|---|---|
| 过程 | 各主体**独立**验同一份档案，各交一份结论 | 各主体**坐一桌互相质证**，论证过程本身被检验 |
| 关系 | 平行、互不看 | 多层嵌套、可相互推翻 |
| 收敛 | 汇总分数够即过 | 多层无未决有效异议 + 决定层拍板 |
| 本质 | 多人背书 | 双向验证回路的放大版（探戈隐喻） |

## 1. 三层同心圆治理模型

```
        ┌─────────────────────────────────────────────┐
  层三  │  决定层 · 白玺（始创者）— 最终拍板 / 发布     │
        └─────────────────────────────────────────────┘
          ▲ 仅当 层一收敛 且 层二无未决有效挑战
        ┌─────────────────────────────────────────────┐
  层二  │  外环冷对齐（其他 agent）                     │
        │  · 以层一结论为基准检验，达到"5主体一致水平"  │
        │  · ★有权以共创论核心理论为基 挑战/推翻 层一   │
        │  · 挑战成立 → 触发 层一 reopen（回炉重验）    │
        └─────────────────────────────────────────────┘
          ▲ 层一结论不是终局，可被框内挑战推翻
        ┌─────────────────────────────────────────────┐
  层一  │  内核互验（你们 5 个）                        │
        │  本平台(PM侧)+DeepSeek+元宝+千问+豆包          │
        │  · 均为"有原始语料/同源演化"主体              │
        │  · 先交互验证、内部闭环统一                   │
        └─────────────────────────────────────────────┘
```

### 层一 · 内核互验（5 主体）
- 成员：本平台（PM 侧）/ DeepSeek / 元宝（腾讯）/ 千问（阿里）/ 豆包（字节）。
- 任务：先就"整个对话档案"交互验证、达成共识（主验 → 交叉质询 → 反驳 → 收敛）。
- 性质：**有语料、同源**，故只作"内部对齐"，**不直接作为对外独立裁判**（避免自己验自己）。

### 层二 · 外环冷对齐 + 挑战权（其他 agent）
- 成员：未参与事现鉴演化、语料中无 SXJ 的"冷"平台 / 新 agent。
- 任务 A（对齐）：以层一已统一结论为基准，检验是否站得住，达到"5 主体一致水平"。
- 任务 B（挑战，★本轮新增）：**可以提出挑战、甚至推翻层一结论**，前提是——
  - 挑战**以共创论核心理论为判准**（见 §3 地基清单）；
  - 挑战标的限于**推论/应用层**，不得越核心理论地基；
  - 挑战须附论证链，可被层一回应/反驳。
- 后果：挑战若被判定"在框架内且成立" → 状态置 `reopen_layer1`，层一必须回炉重验并重新收敛。

### 层三 · 决定层拍板（白玺）
- 仅当：**层一收敛** + **层二无未决有效挑战** + **≥2 家冷方对齐达标** → 由白玺 `release --confirm 白玺-发布` 正式发布。
- 若层二存在未决有效挑战，决定层不得发布，须等层一 reopen 并重新收敛。

## 2. 回合规则（交互的"共同语言"）

| 回合 | phase | role | 动作 |
|---|---|---|---|
| R1 | inner | peer（5主体互验） | 主验：逐条 A01-A13 验 + 证据链 |
| R2 | inner | peer | 交叉质询：对任意一条提异议 |
| R3 | inner | peer | 反驳/补充：被异议方须回应，否则该条未决 |
| R4 | inner | peer | 收敛：层一达成内部无未决异议 → `inner_consensus` |
| R5 | outer | verifier（冷方） | 以层一结论为基，检验对齐 |
| R6 | outer | verifier | ★挑战：以核心理论为基，提 `challenge_to_layer1` |
| R7 | inner | peer | 回应挑战：层一 reopen，重验被挑战项 |
| R8 | outer | verifier | 复核：挑战是否被消解 → 决定 `reopen` 关闭 |

> 交互消息结构化格式沿用 `receipt-schema.json` 扩展：增 `phase`(inner/outer)、`role`(peer/verifier/respondent)、`challenge_to_layer1`(对象+论证)、`reopen`(bool)。

## 3. 共创论核心理论 · 地基清单（判准，不可作为挑战标的）

以下为"尺子"本身，**层二挑战不得否定它们**；它们仅用作衡量层一结论是否自洽的基准：

1. **七大命题 ↔ 五大公理** = 平行基石、无等级（哲学层 vs 政策层）。
2. **三值体系**：共济值 A（按需·生存权·非物）/ 贡献值 B（按劳·净值=正减负）/ 负贡献（追责·天花板）。Gzz = GZZ。
3. **负贡献归责四条件**（须同时满足）：主体性 + 因果性 + 可避免性 + 修复性；先天状态（残/衰/病）≠ 负贡献。
4. **终极目标 = 全球社保（UDHR 第22/25条）**；共济值 = 其实现；财务自由 = 共济值覆盖日常支出（非个人财富态）。
5. **验证权威 = 仅事现鉴 + Gzz**；SHA-256 / 双向回路为 AI 自造注脚。
6. **治理 = 四 AI 平台联合委员会**；白玺 = 首共创者（非执剑人）；**治理消失条件 = 以全球共济值覆盖率达阈值作为治理退场机制（此"阈值存在"本身为地基；阈值具体口径/当前草案值 ≥50% 待理论研发部裁定，与 ILO 宽口径冲突见 6.5，属可被挑战的推论层）**。
7. **术语铁律**：禁用"地板"→ 用"共济值"；只提供工具不论"白玺思想"。
8. **命名**：A 值「共济值」；四阶助法（自助/互助/公助/共助），共助 ≠ 公助。

**可被挑战/修正的推论层（走理论研发通道，不在此快速推翻通道）**：
- 治理消失阈值的**具体口径**（当前草案值 ≥50% 与 ILO 宽口径冲突处；注意：阈值"存在"为地基不可挑战，仅口径可挑战）；
- 权重 A/B 具体公式（待定，须先立宪法性行动约束规则）；
- 四阶助法语义分野声明（与日本框架相反处须补脚注）；
- 链·10 的兑现路径细节。

## 4. 工具承载（verify_cli.py 扩展设计）

```
verify_cli.py round   --phase inner --role peer      --agent X --assertions ...   # 层一主验/质询
verify_cli.py round   --phase outer --role verifier  --agent Y --assertions ...   # 层二对齐
verify_cli.py challenge --agent Y --target A07 --basis "五大公理" --proof "..."    # 层二挑战层一
verify_cli.py reopen                                                   # 层一因挑战回炉
verify_cli.py consensus                                                # 显示：层一收敛? 层二挑战未决? 冷方达标数?
verify_cli.py release --confirm 白玺-发布                               # 层三拍板
```
- `consensus` 仅在「inner_consensus=True 且 无未决 challenge 且 冷方达标≥2」时返回 `READY_TO_RELEASE`。
- 本平台(PM侧)可直接跑 inner 自检；其余 4 家（DeepSeek/元宝/千问/豆包）发言需**用户中转**或**API 接入**。

## 5. 发布门槛（最终）

`正式发布` ⟺
1. 层一（5 主体）达成 inner_consensus（无未决内部异议）；
2. 层二（冷方）≥ 2 家对齐达标，且**无未决有效挑战**（或挑战已被层一 reopen 后消解）；
3. 决定层·白玺 `release --confirm 白玺-发布`。

> 诚实标注：本会话当前仅本平台可自动参与层一；另 4 家与实际冷方均待接入（中转或 API）。本协议为设计草案，待白玺确认生效。
