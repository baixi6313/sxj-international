### 2.4 【P0 阻断】新事现录入通道物理断裂

对小程序 10 个页面 WXML 做结构体检，结果：

```
addEvent.wxml         行数=10   输入控件=1   ← 仅剩「记录人」
addEvidence.wxml      行数=3    输入控件=0   ← 空容器
addVerification.wxml  行数=3    输入控件=0   ← 空容器
verifyGroup.wxml      行数=21   输入控件=0   ← 表单缺失，仅剩列表
events.wxml           行数=21   输入控件=0   ← 三值筛选器缺失
```

**故障链复算**：
- `addEvent.js:6-14` 的 `form` 声明 7 个字段（title/typeIndex/date/location/description/evidence/recorder）；
- `addEvent.wxml` 只渲染 `recorder` 一个输入框；
- `addEvent.js:40-47` 提交前强校验 `form.title` 与 `form.description` 非空；
- → **任何用户点击「保存事现」，必然被 toast「请填写标题」拦下，新事现 100% 提交失败。**

同理：`addEvidence` / `addVerification` 为空容器 → **无法追加证据、无法提交验证意见** → 第二层（验证层）与第三层（共识哈希链）**全部失去数据入口**。
`events.wxml` 仍在用 `wx:if="{{filter === 'all' || item.type === filter}}"` 过滤，但**筛选按钮已不存在**，`filter` 永远为默认值。

**归因**：与 `pm/ygzz02_audit.md:113` 记录的 `profile.wxml` hero 区块被误删属**同一根因**——`remove_banner.py` 贪婪正则误伤。审查当时**只发现并修复了 `profile.wxml`，遗漏了 addEvent / addEvidence / addVerification / verifyGroup / events 五个页面**。

> ⚠️ 这意味着：**在本报告讨论「新记录事件的展望」之前，必须先承认——目前没有任何新事件能被记录进小程序。** 这是事现验证部当前的头号阻断项。

| 权威冒充 | 以「专家/记者」身份背书，用名气替代证据 | ✅ 理论已防：`验证团定义v2` 明确「名气零导入」 |
| 沉默压制 | 利害方组织不投票，使真事现永远达不到共识阈值 | ⚠️ 无 |

**A. 双向回路——把「验证」和「后果」绑死**

事现鉴的本质定调是「现实世界与互联网世界的**双向**验证机制」（`2026-07-25.md:211`）。反刷量的关键就在**回路的下半程**：

- **单向系统**（现实→数字）刷量零成本：刷完就走，数字记录不反作用于刷手。
- **双向系统**（数字→现实）刷量有代价：验证意见一旦上链，就与验证人的 CV 净值绑定；事现后续若被推翻，**当初投「确认」的人的 CV 按其表态强度反向扣减**。
- **落地建议**：为每条验证意见增加 `stake` 字段（表态强度：弱确认/强确认/担保），强度越高，被推翻时反噬越大。**让「随手点确认」和「我拿信用担保」在账本上是两回事。**

**B. 人头票——严守「B 不替票」**

`权重数值公式公开征集启事.md` 已锁死 7 条硬约束，其中三条直接对应反刷量，**必须在事件簿实现中原样落地**：
- **人头票驱动**：共识达成靠人数与社区热点，不靠权重加总；
- **B 不替票**：贡献值（B）高的人**不能用 B 抵票数**，B 只影响归责与公信力修正，**不影响共识是否达成**；
- **优雅退化**：参与人数不足时，系统应输出「共识未达成」而非用权重补足。

> 这条约束的反刷量意义：即使攻击者刷出巨额 CV，也**买不到一票**。攻击成本从「刷分」被迫回到「拉真人」，而拉真人本身即受实名/openid 唯一性约束。

**C. 共识判定——建议引入三道闸**

| 闸 | 规则 | 防的是 |
|---|---|---|
| 闸 1 · 独立性 | 同一事现中，**有利害关系方的表态单独计列，不计入共识票数**（可计入证据） | 自证、当事方刷票 |
| 闸 2 · 异源性 | 状态升入 `verified` 至少需 **2 个互相独立的证据源**（不同机构/不同渠道/不同提交人） | 单点伪造 |
| 闸 3 · 冷却期 | 任何状态升级须**公示 N 日**，期间可被质疑冻结 | 突击刷票 |

**D. 关键前提：负样本必须有位置**

目前六状态里 `invalid 未成立` **一条都没有**。一个从不判「不成立」的验证系统，其「已验证」是无意义的。
**建议**：主动补记 1–2 条经核查后判定为 `invalid` 的事现，作为系统可证伪性的实证。**这比再增加十条「已验证」更能提升平台可信度。**

### ② 负贡献归责四条件如何落到事件簿表单

**理论现状（已锁）**：`whitepaper.html:150` —— 归责须**同时满足**主体性 / 因果性 / 可避免性 / 修复性；先天状态（残疾/衰老/疾病）≠ 负贡献（`2026-07-26.md:14-19`）。

**实现现状（缺口）**：`events.html:87-114` 的表单字段为「标题 / 三值类型 / 日期 / 描述 / 证据 / 记录人」——
**当类型选择「负贡献」时，表单不发生任何变化，四条件无处填写、无处校验、无处展示。**
→ 理论层最严谨的一条原则，在产品层**完全没有落点**。

**落地方案（提案 · 三步）**

**第一步：类型联动的四条件子表单**
类型选为「负贡献」时展开 4 个必填结构化字段：

| 条件 | 表单字段 | 填写要求 | 校验口径 |
|---|---|---|---|
| **主体性** | 责任主体是谁？其在行为时是否具备行为能力与选择空间？ | 必须指名到具体主体（自然人/法人/机构），**不接受「社会」「体制」等无主体表述** | 无法指名 → 阻断提交 |
| **因果性** | 该行为与损害之间的链条如何？ | 需描述可追溯的因果链，**区分「相关」与「导致」** | 仅有时间相关 → 降级为「线索」 |
| **可避免性** | 当时是否存在不造成该损害的可行替代方案？ | 需指出替代方案，**先天状态、不可抗力在此条自动出局** | 无替代方案 → **自动判定不构成负贡献** |
| **修复性** | 损害是否可修复？修复路径与成本？ | 对应 Gzz 化债机制（正贡献对冲负贡献） | 决定后续 `resolved` 的判定标准 |

**第二步：四条件即状态机的硬闸**
```
四条件全填 + 全部成立  → 允许升入 verifying
任一条件明确不成立     → 强制判定 invalid（未成立），并留痕理由
四条件填写不全         → 冻结在 recording，不得升级
```
> 这样「先天状态 ≠ 负贡献」**不再是白皮书里的一句话，而是表单层拦不过去的硬约束**。

**第三步：用彬县 evt_BX_1998_001 做首个试填样例**
该案四条件应能填出但**结论不应是「已归责」**，正好检验闸门有效性：
- 主体性：需明确是「彬县卷烟厂改制主体」还是「陕西省中烟工业公司」还是「当年经办机构」——**目前恰恰不清楚，这正是该案卡在 recording 的真实原因**；
- 因果性：改制 → 断缴 → 档案缺失，链条方向清楚但**每一环的证据均缺**；
- 可避免性：需查 1998 年改制政策是否强制要求接续社保——**可查，但尚未查**；
- 修复性：补缴 / 一次性补偿 / 档案重建，**三条路径可列**。

→ 把四条件字段一填，**该案「差什么」立刻结构化显形**，比现在一段散文式描述有用得多。这也是四条件表单最直接的价值：**它不只是归责工具，更是「取证任务清单生成器」。**

### ③ 与全球社保断档案例库的衔接

**定位判断**：彬县 evt_BX_1998_001 **不应只是一条中国负贡献案例**。

理论侧已有明确接口：`2026-07-25.md:138-144` 记载「全球社保·事现鉴（跨国权益可验证）——国际」「事现鉴是全球社保的核心理念，是三把验算尺中的国际端」；终极目标定调为 **UDHR 第 22 条**（`2026-07-27.md:6`）。

**彬县案的国际可比性（这是它的真正价值）**：

| 结构要素 | 彬县案 | 全球同构场景 |
|---|---|---|
| 触发事件 | 1998 国企改制 | 私有化 / 企业破产 / 主权债务重组 |
| 断裂物 | 社保缴费记录 + 人事档案 | 养老金权益 + 缴费凭证 |
| 制度失灵 | 监察无预算、社保无档案、纪委证据灭失、信访无执法权 | **权责分散导致集体无解** |
| 当事人处境 | 有理说不清，走访多次无结果 | 跨境劳工、移民、失联雇主 |

→ **共通结构：「权益真实发生过，但记录载体消失，制度无人能证」。这正是全球社保断档的元问题。**

**衔接建议（四条）**
1. **建立统一案例 Schema**：`evt_{国家/地区码}_{年份}_{序号}`。彬县已有 `evt_BX_1998_001` 雏形，**建议正式确立为命名规范首例**（`BX`→建议规范化为 `CN-BX`）。
2. **抽象「断档五要素」结构化字段**：断裂时点 / 断裂原因 / 缺失凭证类型 / 现存替代证据 / 责任主体链。彬县案五项**已具备四项，仅「责任主体链」待明确**。
3. **对接 UAXS 统一凭证**：`pm/org/access-standard.md` 定义的 SXJ-VC 凭证与 VERIFY/ATTEST/CONSENSUS 三类报文，**恰好是断档案例跨境互认的载体**——境外机构无法核验中国档案，但可核验哈希链与共识回执。
4. **国际版内容策略**：hygzz.com 目前不含彬县案（`2026-07-30.md:83` 记「该事现为中国语境，留在国内版」）。**建议重新评估**——去除具体机构名后的**结构化抽象版本**（"1998 SOE restructuring pension gap, N claimants, records lost"）恰恰是国际版最有说服力的内容，且规避了本地敏感性。

> ⚠️ **前置条件**：在案例进入国际库前，**必须先完成第三方核查**。当前它仅有利害关系方举证。**把未验证案例推向国际，等于把项目最大的信誉风险敞口对外放大。** 顺序不能颠倒。

### ④ 事件簿与知识树 / 白皮书如何互相引用

→ **同一 ID，两处溯源互相矛盾**（DeepSeek 对话 vs WorkBuddy 对话）。理论侧记的是「概念从哪来」，事实侧记的是「证据从哪来」，**二者混用了同一个「来源」字段名**，读者无法分辨。

**双向引用协议提案（四条）**

1. **建立唯一事现 ID 作为跨文档主键**
   全项目统一到 `evt_xxx` 一套命名（A 账本的 `seed1-6`、D 账本的 `seed1-4` 全部映射过去），ID 即锚点：`events.html#evt_007`。

2. **理论 → 事实：知识树/白皮书的每个「应用」节点挂事现锚链**
   知识树 463 行的彬县节点应渲染为可跳转链接，并**实时显示该事现当前状态徽标**。
   > 关键价值：知识树里写着「政府第三方尺」这一理论主张，点进去看到的是 **`记录中 · 未经第三方核查`**。**理论的成色被事实即时标定，说大话会当场露馅。** 这是本项目最值得建的一条约束。

3. **事实 → 理论：事件簿每条事现增加 `theoryRefs` 字段**
   如 evt_007 → `[负贡献四条件, 政府第三方尺, 全球社保断档]`，点击跳知识树对应节点。

4. **拆分「来源」字段，消除上述矛盾**
   | 字段 | 含义 | 彬县案取值 |
   |---|---|---|
   | `conceptSource` | 概念/框架从哪次讨论来 | 用户与 DeepSeek 对话 2026-07-31 |
   | `evidenceSource` | 事实证据从哪来、什么性质 | 白玺亲历口述 + 群聊截图（有利害关系方举证） |
   | `provenanceLevel` | 证据强度分级 | **L1 单方举证**（建议分级：L0 AI 演绎 / L1 单方举证 / L2 多方互证 / L3 第三方核查 / L4 官方通报） |

   > 引入 `provenanceLevel` 后，2.3 节的「死声明」问题自动消解——**总体声明不必再靠一段文字，每条事现自带强度标签**。且新增事现时强制选级，声明不会再滞后于数据。
