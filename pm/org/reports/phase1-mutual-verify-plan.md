## 1. 为什么是"相互检查"而非"各交一份"

用户明确要求"相互检查"= 四家**坐一桌**互相看论证、质询、收敛，不是各自封闭打分。这正是事现鉴"双向验证回路"的放大版。对应《交互验证治理协议 v1》的**层一·内核互验**。

四家均有原始语料 → 定为**同源主体**，仅作内核对齐，**不计入**第③步外部冷方门槛（避免自己验自己）。

## 2. 中转操作（用户当传声筒，因无 agent 互调 API）

1. 用户把 `sxj-verify/phase1-package.md` + 档案全文 + claims 全文，分别发给四家。
2. **Round 1**：四家各自独立初验，回传 JSON → 用户把四份 JSON 合成一个数组文件 `r1.json`，运行：
   `python verify_cli.py round --round 1 --file r1.json`
3. **Round 2**：用户把每家 R1 贴给另外三家 → 四家出 challenge/rebuttal，回传 → 合成 `r2.json` → `round --round 2 --file r2.json`
4. **Round 3**：用户把 R2 的 challenge/rebuttal 转贴 → 四家出终验（outstanding/consensus_reached）→ 合成 `r3.json` → `round --round 3 --file r3.json`
5. 运行 `python verify_cli.py phase1-status` 看收敛。

> 若某家支持 API 且用户愿提供，可改为脚本自动拉取（见《交互验证治理协议 v1》B 方案），但当前按中转执行。

## 3. 收敛判定

`phase1-status` 汇总最后一轮四家的 `outstanding` 与 `consensus_reached`：
- 四家 `outstanding` 均为空 且 多数 `consensus_reached=true` → **内核收敛达成** → 进入第③步。
- 存在未决 `outstanding` → 打印待解项，建议 `reopen` 加轮。

## 4. 与第③步的衔接

内核收敛结论 = 第③步外部冷方的检验基准。外部冷方**可以**以核心理论为尺挑战内核结论（层二挑战权），但挑战须基于事现鉴自身地基，不成立则内核结论维持。

## 5. 防作弊

- 每家回传须回填档案 SHA256，与 `phase1-state.json` 锁定值不符则拒收。
- 用户中转时不得擅自改写四家言论；中转仅搬运，不替任何一方作答。
