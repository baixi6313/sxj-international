# 组织架构提案（总经理视角）

> 现状：已设 **光锥运维部**（hygzz01/02/03），负责日常维护闭环。
> 本文是总经理对"还应组建哪些部门、设哪些角色、架构怎么搭"的提案。
> ⚠️ 本部门内新建 agent 可由总经理自由建立；**跨部门的任何新 agent / 新部门，须经用户许可后落地**。

## 一、建议的组织架构（总览）

```
                      总经理 (GM = WorkBuddy 主会话)
                                  │
        ┌──────────────┬──────────┴──────────┬──────────────┬──────────────┐
        │              │                     │              │              │
   光锥运维部      事现验证部           理论研发部       对外协作部      安全合规部
   (已成立)       (建议新设)          (建议新设)       (建议新设)      (建议新设)
   日常维护闭环    事现/共识/验证网络   共创论/白皮书/知识树  四大域/平台对接/凭证接入  密钥/凭证/隐私/备案
        │              │                     │              │              │
   横向支撑 ──────────────────────────────────────────────────────────────┘
   （运维部以"部署/审查/优化即服务"支撑所有部门）
```

> 另设 **产品体验部**（用户本人任产品设计师，总经理任工程实现）作为需求入口，不单列 agent，直接并入 GM 工作流。

## 二、各部门职责与角色

### 1. 光锥运维部（已成立）
- 角色：hygzz01 记录员 / hygzz02 审查员 / hygzz03 优化师（可经许可扩编）。
- 范围：网页(hygzz.com/cn/top) + 小程序 + App 的部署、审查、优化。

### 2. 事现验证部（建议新设）
- **使命**：维护"事现"这一核心资产——事件簿、三值/六状态模型、验证人网络、共识机制。
- 角色草案：
  - 验证官（Verifier）：执行/编排单次验证，签发带 SHA-256 指纹的事现凭证。
  - 共识协调（Consensus Lead）：运营人头票/社区热点驱动的共识判定。
  - 事件簿维护（Ledger Keeper）：维护 events.html 与种子事件、状态机流转。
- 关联：白玺＝首共创者节点；四 AI 平台联合委员会＝治理层。

### 3. 理论研发部（建议新设）
- **使命**：共创论 8.0、七命题/五公理、三值模型、白皮书、知识树的权威内容与演进。
- 角色草案：
  - 理论架构师（Theorist）：命题/公理/权重边界的定稿。
  - 白皮书编辑（Editor）：对外文档一致性。
  - 知识树策展（Curator）：把新知识按 v1.2 风格归入知识树（即 hygzz03 优化产出的落点之一）。

### 4. 对外协作部（建议新设）
- **使命**：四大域运营、与各 AI 平台/大厂对接、统一对外接入标准（见 access-standard.md）的接入管理。
- 角色草案：
  - 平台关系官（Liaison）：对接 DeepSeek/元宝/千问/豆包/WorkBuddy/Cloudflare 等。
  - 凭证管理员（Credential Admin）：签发/轮换 SXJ-VC 统一凭证（与安全合规部共管）。
  - 合规/备案（Compliance）：备案号、隐私政策、商店上架对接。

### 5. 安全合规部（建议新设）
- **使命**：密钥与凭证的全生命周期管理、隐私与备案、审计。
- 角色草案：
  - 安全官（SecOps）：密钥扫描闸门、.gitignore 加固、令牌轮换策略。
  - 凭证签发（Issuer）：以根密钥签发 SXJ-VC，维护吊销列表。
  - 审计（Auditor-sec）：定期复核权限边界（呼应 Cloudflare User/Account/Zone 三层。

## 三、汇报与协作机制
- **GM** 是唯一对用户回报的节点；各部门产出经 GM 汇总。
- **矩阵式支撑**：光锥运维部提供"记录→审查→优化"通用流水线，其他部门的需求经 GM 转运维部执行落地。
- **统一凭证**：由安全合规部 + 对外协作部共管，GM 批准签发策略（详 access-standard.md）。
- **决策原则**：理论权威＝仅事现鉴+Gzz；治理消失条件＝全球共济值≥50%。

## 四、落地顺序建议（需用户许可后逐步建）
1. 先建 **安全合规部**（解决当前明文 PAT / COS 密钥散落的高危问题）。
2. 再建 **事现验证部**（核心资产专人管）。
3. 然后 **理论研发部**、**对外协作部**。
4. 每建一个部门，先定 1 个最小角色，跑通后再扩编。
